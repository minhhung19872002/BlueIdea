# Iteration 4 — P0 Security: REQ-21 Auth Vulnerabilities (Account Enumeration + SSO State + Open Redirect)

## What Was Worked On

Three HIGH security vulnerabilities in the authentication system (REQ-21, REQ-41):

1. **Account enumeration via distinct login error messages (HIGH)**: Login endpoint returned different error codes (`TaiKhoanBiKhoa`, `TaiKhoanChuaKichHoat`) for locked/inactive accounts vs. nonexistent accounts, allowing attackers to enumerate valid usernames. Fixed in both password login (`DangNhapCommand`) and SSO login (`DichVuDangNhapSso`).

2. **SSO state parameter not validated server-side (HIGH)**: The OIDC state parameter was generated by the server but never stored or checked back — only client-side verification existed. Added server-side state storage in `IMemoryCache` with 5-minute TTL, one-time-use validation in `DoiMaSsoAsync`, and added `State` field to `DoiMaSsoDto`. Frontend updated to send state back with code exchange.

3. **Open redirect in duongDanTraVe (HIGH)**: SSO redirect URI (`duongDanTraVe`) was validated only for format (absolute HTTP/HTTPS URL) but not for host. An attacker could redirect to any external domain. Added `KiemTraDuongDanTraVe` helper that validates scheme+host+port against allowed origins from `Cors:NguonChoPhep` and optional `Sso:AllowedRedirectHosts`. Applied to all three SSO endpoints.
